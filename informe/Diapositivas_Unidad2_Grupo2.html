De vitrina estática a app interactiva

Unidad I → Unidad II

  • En la Unidad I: solo UI estática (StatelessWidget), controles decorativos.
  • Ahora activamos la interacción: favoritos, carrito, filtros y pedido.
  • Tres pilares nuevos: Estado, Persistencia y Formularios.
  • El corazón ♥ y el botón 🛒 que antes “no hacían nada”, ahora funcionan y recuerdan tus datos.

¿Qué es el estado?

  • Estado = los datos que cambian y que la interfaz debe reflejar.
  • Estado local (setState): efímero y propio de una pantalla → búsqueda y filtros del catálogo.
  • Estado compartido (provider + ChangeNotifier): usado por varias pantallas → favoritos y carrito.
  • Regla práctica: si varias pantallas lo necesitan → provider; si es solo de una → setState.
// Estado local en el catálogo
onChanged: (v) => setState(() => _busqueda = v);
onSeleccion: (c) => setState(() => _categoria = c);

provider + ChangeNotifier

class CarritoProvider extends ChangeNotifier {
  final Map<String, ItemCarrito> _items = {};

  double get total => _items.values
      .fold(0.0, (s, i) => s + i.subtotal);

  void agregar(Producto p) {
    // ...suma o incrementa...
    notifyListeners();  // la UI se redibuja
    _guardar();         // persiste
  }
}
  • Una sola fuente de verdad para el carrito.
  • notifyListeners() avisa a la UI.
  • Inyectado con MultiProvider en la raíz.
  • Badge en la barra inferior muestra el conteo en tiempo real.
  • context.select → solo se redibuja la tarjeta afectada (eficiente).

Persistencia con shared_preferences

  • Almacenamiento local clave–valor en el dispositivo.
  • Favoritos → favoritos_ids (lista de ids).
  • Carrito → carrito_items (JSON).
  • Se guarda tras cada cambio y se carga al abrir la app.
  • Resultado: cierras la app y tus datos siguen ahí.
// Flujo
UI  ─►  Provider  ─►  SharedPreferences
 ▲          │                 │
 └─notify───┘◄──── carga ──────┘
await prefs.setStringList(
    'favoritos_ids', _ids.toList());

Serialización JSON

// Guardar el carrito
prefs.setString('carrito_items',
  jsonEncode(_items.values
     .map((i) => i.toJson()).toList()));

// Cargar y reconstruir
for (final e in jsonDecode(raw)) {
  final item = ItemCarrito.fromJson(e);
  _items[item.producto.id] = item;
}

toJson() / fromJson() convierten objetos ↔ texto.

Formularios y validación

final _formKey = GlobalKey<FormState>();

void _enviar() {
  if (!_formKey.currentState!
         .validate()) return;
  // ...confirmar pedido...
}

// Validador del celular
validator: (v) {
  if (!RegExp(r'^9\d{8}$')
      .hasMatch(v ?? ''))
    return '9 dígitos, inicia con 9';
  return null;
}
  • Form + GlobalKey<FormState> coordinan todo.
  • TextFormField con validadores: nombre, celular, correo, dirección.
  • DropdownButtonFormField: entrega, distrito y pago.
  • inputFormatters: solo dígitos en el celular.
  • Validación condicional: la dirección solo si es Delivery.

Demostración: checkout

  • Al tocar Confirmar con campos vacíos → aparecen los errores en rojo.
  • El resumen muestra 3 producto(s) · Total S/ 102.00.
  • Si todo es válido → diálogo de confirmación y se vacía el carrito.
  • Flujo completo: Catálogo → ♥ Favoritos → 🛒 Carrito → Checkout.

Conclusiones

  • Integramos los tres pilares: estado, persistencia y formularios.
  • provider + ChangeNotifier mantiene el código limpio y escalable.
  • shared_preferences hace que favoritos y carrito sobrevivan al cierre.
  • Form + validación garantiza datos correctos antes de confirmar.
  • flutter analyze sin incidencias · pruebas en verde · app compilada.
