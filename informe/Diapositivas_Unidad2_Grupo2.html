Gestión de Estado: MultiProvider

// lib/main.dart
MultiProvider(
  providers: [
    ChangeNotifierProvider(create: (_) => TemaProvider()),
    ChangeNotifierProvider(create: (_) => FavoritosProvider()),
    ChangeNotifierProvider(create: (_) => CarritoProvider()),
  ],
  child: const AromaSagradoApp(),
);
  • Una sola fuente de verdad: Cada provider notifica exclusivamente a sus suscriptores mediante notifyListeners().
  • Reactividad selectiva: context.watch<T>() para redibujar y context.read<T>() para despachar acciones sin reconstruir.
  • TemaProvider: Alterna entre ThemeMode.light y ThemeMode.dark persistiendo la elección.
  • CarritoProvider: Controla items, cantidades, subtotal, costo de envío y cálculo de total.
  • FavoritosProvider: Colección reactiva de productos guardados.
// Lectura reactiva en widgets
final tema = context.watch<TemaProvider>();
final carrito = context.watch<CarritoProvider>();

Controladores y Ciclo de Vida (dispose)

Criterio 1 de Rúbrica: Prevención de Memory Leaks

  • En aplicaciones móviles, los controladores no liberados consumen recursos de memoria RAM indefinidamente.
  • Se implementó rigurosamente la liberación en el método dispose() en todas las pantallas con estado:
  • 6 TextEditingControllers: Nombre, teléfono, correo, dirección, referencia y notas.
  • 6 FocusNodes: Gestión fluida de teclado entre campos.
  • ScrollController: Control de desplazamiento y botón flotante de retorno.
  • StreamSubscription: Cancelación de escucha de eventos del acelerómetro.
// lib/screens/checkout_screen.dart
@override
void dispose() {
  _nombreCtrl.dispose();
  _telefonoCtrl.dispose();
  _correoCtrl.dispose();
  _direccionCtrl.dispose();
  _referenciaCtrl.dispose();
  _notasCtrl.dispose();
  for (final node in _focusNodes) {
    node.dispose();
  }
  super.dispose();
}

Patrón Repositorio: PedidoRepository

// lib/data/pedido_repository.dart
class PedidoRepository {
  // CREATE: Inserta pedido y retorna id
  Future<int> crearPedido(Pedido p);

  // READ: Filtro por estado y búsqueda segura
  Future<List<Pedido>> obtenerPedidos({
    String? estadoFiltro,
    String? queryBusqueda,
  });

  // UPDATE: Actualiza ciclo de entrega
  Future<int> actualizarEstado(int id, EstadoPedido nuevo);

  // DELETE: Borra registro y foto física
  Future<int> eliminarPedido(int id);
}
  • Consultas Parametrizadas: Uso estricto de whereArgs en SQLite para prevenir inyecciones SQL.
  • Limpieza de Archivos Físicos: Al invocar eliminarPedido(), se valida y borra la imagen física del comprobante del disco del dispositivo móvil.
  • Validación Asíncrona: Método existePedidoActivo(telefono, correo) para detectar duplicados en curso antes del submit.

Formularios y 6 Validaciones Robustas

GlobalKey<FormState> · Validación en Vivo

  • 1. Nombre completo: Requerido, longitud ≥ 3 caracteres.
  • 2. Correo electrónico: Validación con RegExp RFC 5322.
  • 3. Celular peruano: Exactamente 9 dígitos iniciando en 9 (^9[0-9]{8}$).
  • 4. Dirección de entrega: Obligatoria, ≥ 5 caracteres.
  • 5. Distrito: Selección obligatoria de distrito del Cusco.
  • 6. Validación Asíncrona SQLite: Alerta si el cliente ya tiene un pedido en estado pendiente o en camino.
  • Prevención de Doble Envío: Bloqueo inmediato del botón durante el guardado (_enviando = true).

Sensor Acelerómetro: Shake Gesture

Detección interactiva de movimiento (sensors_plus)

  • Algoritmo de sacudida: Se monitorea el flujo de aceleración espacial con gravedad:
    fuerza = sqrt(x² + y² + z²)
  • Al sobrepasar el umbral cinético (15.0 m/s²) se desbloquea una animación festiva y el Cupón del 15% de descuento.
  • Simulación para Evaluadores: Incluye un botón en pantalla para simular la sacudida en emuladores o entornos de escritorio.
  • Suscripción segura: Cancelación de la suscripción en dispose() para ahorrar batería.
// lib/screens/ofertas_screen.dart
_sub = accelerometerEvents.listen((e) {
  final g = sqrt(e.x * e.x + e.y * e.y + e.z * e.z);
  if (g > 15.0) {
    _desbloquearCupon();
  }
});

Navegación Avanzada y Rutas Tipadas

Navegación declarativa y paso seguro de objetos

  • Rutas nombradas: /, /checkout, /pedidos, /ajustes, /ofertas.
  • Paso de argumentos tipados:
    • /producto/detalle recibe el objeto Producto con pestañas de origen, altitud y garantía.
    • /pedidos/detalle recibe el objeto Pedido de SQLite.
  • Retorno reactivo: Al cambiar el estado de un pedido y retornar con Navigator.pop(context, true), el historial SQLite se recarga automáticamente.
